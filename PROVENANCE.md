# Provenance of this repository (Paper E)

## 0 Baselines used in this file

Three states are compared: (1) the author's tree `old_archive/1_sources/sources/<paper>`; (2) the first Zenodo release (the initial git commit of this repository); (3) the current repository. On 2026-10-21 (1) and (2) were compared byte for byte: they are identical except for the repository metadata (`.gitignore`, `.zenodo.json`, `CITATION.cff`), the compiled PDF. The rest of the old archive (`old_archive/2_docs_and_archive_1/archive/`: earlier manuscript versions, session logs, audit directories) was searched for code and data behind this paper's results; files found there that are not in the Zenodo release are listed below where they matter. Wherever this file says "original" or "v1.0.1" it means (1) = (2).

## 1 Lineage

This repository is a reorganization of the author's original archive of Paper E (Zenodo v1.0.1; "original" below). Reorganization means:
a README, LICENSE, CITATION.cff, requirements, a Makefile, `verify.sh`/`verify.py`/`verification/`, and the stored output of the verification were added.
On 2026-10-21 every file was compared with the original (`diff -rq`, byte and numerical comparison): all 290 original files are present,
272 were byte-identical and 18 differed (6 of them documentation or manuscript files); in this version 6 of the 18 are restored to the original content (section 2), so 12 differ; 67 files are new (section 3, of which 31 are verification logs).
The comparison and the reproductions in section 5 were made by an automated provenance audit (Claude), not by the author.
Nothing in this file is a new result. Where a number of the paper is not backed by original code, section 3 says so.

## 6 Known limits

* Quick mode (`verify.sh`) regenerates the cheap jobs. It does not regenerate: the threshold scans at h = 0.04, 0.02, the domain, universality, supercritical, checks, kappa-scan and sign-scan runs, and the eight five-grid `gen3_*.json` inputs (hours; `--full`). The checks of about 110 numbers read the stored original outputs of these runs. The README reports `full_gen3_B0.003_k1.5_v300` (bit-identical) and `full_threshold_h0.04` (5e-12) as run by the reorganizer; the audit did not repeat them.
* The 49 symbolic checks are read from `code/symbolic_checks.log` (sympy 1.14.0) when sympy is absent.
* Tolerances: `digits` means half a unit of the last quoted digit, so values quoted with one or two digits accept deviations of up to 17%; 55 of 369 numeric checks accept more than 1% and 12 more than 5% (largest: "about 1e11" vs 1.17e11, 3e-6 vs 2.63e-6, 3e-7 vs 3.34e-7, 4e-4 vs 3.56e-4). Eight checks use a multiple (x1.1-x1.5) of the half unit; `le`/`ge` bounds can have large slack. Details: the audit report of Paper E, section E.
* `Mext`/`Mlev` of the gen2- and gen3-based B = 0.003, k = 3/2 runs differ (M_ext(60) 0.8519 vs 0.8475); the paper quotes only the gen3-based q_M(2500) = 5.02, 3.01 (k = 3/2, 1/2).
* The REPORT drift column is informational (no threshold). It now ignores a number only if it is below 1e-9 of the largest number on its own line.
* Statements taken from other papers and not recomputed here: the sigma_v percentages (Paper G), the Bonanno/Carballo-Rubio equation comparisons (literature, not checked by code).
